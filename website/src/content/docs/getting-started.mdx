Just looking? The [live demo](https://demo.goliash.dev) needs no install. Or one command runs a throwaway server with three weeks of example data and prints a link that signs you
in; nothing is kept when you stop it:

```sh
docker run --rm -p 8080:8080 ghcr.io/pipozzz/goliash try
```

The rest of this page starts a server to keep with Docker Compose, shows example data, and connects your first
orchestrator. It takes about five minutes.

## 1. Start the server

```sh
curl -fsSLO https://raw.githubusercontent.com/pipozzz/goliash/main/docker-compose.yml
docker compose up -d
docker compose logs goliash | grep link=        # open it to create your account
```

The server listens on [http://localhost:8080](http://localhost:8080) and keeps its SQLite database in a Docker volume.

## 2. Create your account

Open [http://localhost:8080](http://localhost:8080): for the first 15 minutes after the start, while nobody has an
account, the sign-in page offers **Create the first account**. Enter your e-mail and a password: you are the owner of
the organization and signed in. Later the offer is gone from the page and the one-time **setup link** is only in the
server log (the last command above shows it); it works once, for 24 hours, and restarting the server writes a new one.
Invite the others from **Settings → Users**.

## 3. Look around with example data (optional)

The empty overview shows **Get started** with the next step highlighted. Below it, **Explore with example data**
opens a separate *Example* workspace with three weeks of realistic history: four targets, seven services, rollouts,
drift and new upstream releases. Your own workspace stays empty and clean; switch back in the workspace menu at the
top and delete *Example* under **Settings → Workspaces** when you are done.

To put the example data into the current workspace instead, run `docker compose exec goliash goliash demo`; its
targets are named `demo-*`, so they are easy to tell apart from real ones.

## 4. Connect what you run

There are two ways to collect a target.

<Tabs>
<TabItem label="With an agent">

An agent runs next to the orchestrator and sends snapshots to the server over HTTPS. Use it when the server
cannot reach the orchestrator, or when credentials must stay in that network.

1. Open **Connect** (on the matrix of a new installation, or **Settings → Agents and targets → Connect a cluster or
   host**) and pick what to watch: Kubernetes, a Docker host, Swarm, Nomad, ECS or Compose files.
2. Fill in one form: the name, the environment (pick one or name a new one), **a new agent**, and the platform's
   settings as plain fields.
3. Run the command the next page shows where the agent can reach the orchestrator: Helm for Kubernetes, a compose
   file for Docker, a stack for Swarm, a job for Nomad, a Terraform module for ECS. The token is already in it and
   shown only once.
4. Keep the page open: it shows when the agent connects and what its first report found, then takes you to the
   matrix or the inbox.

The manifests behind those commands are under [Install](/install/).

</TabItem>
<TabItem label="Without an agent">

The server can collect targets itself, with the same read-only collectors: in **Connect**, pick **This server**
instead of an agent. Compose files from Git need nothing else. To watch the Docker host the quickstart runs on,
start its read-only socket proxy and connect a Docker host with the address `tcp://socket-proxy:2375`, or from the
command line:

```sh
docker compose --profile watch-host up -d               # adds a read-only docker-socket-proxy
docker compose exec goliash goliash env create -name prod -position 30
docker compose exec goliash goliash target create -env prod -platform docker -name this-host \
  -settings '{"docker":{"docker_host":"tcp://socket-proxy:2375"}}'
```

</TabItem>
</Tabs>

Within a minute the first snapshot arrives and workloads appear.

## 5. Map workloads to services

Workloads labelled `goliash.service` or `app.kubernetes.io/name` map to services by themselves. Everything else
waits in the **Inbox**, grouped by image with a suggested service name. One click maps every workload that runs the
image and adds a rule, so the next ones map by themselves. See [Matrix and mapping](/guide/matrix/).
